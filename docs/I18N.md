Nếp Mail ships ten interface languages and a per-campaign email language.

## How keys work

Keys are the **Vietnamese source strings** used by the interface:

```ts
t("Tổng quan"); // → "Overview" in English
t("{n} liên hệ", { n: 3 }); // → "3 contacts"
```

Why source strings instead of invented identifiers: an untranslated string
degrades to readable Vietnamese instead of a raw key such as
`contacts.title.empty`, and server messages can be localised without touching
every `throw` site — the message itself is the key:

```ts
// src/core/api.ts
return json({ error: translate(locale, e.message) }, e.status);
```

Resolution order is: locale → English → the key (Vietnamese). ASCII keys
(`email.footer`, `unsub.title`, …) are used for strings that never appear in
the Vietnamese source, and they are defined for all ten languages.

Plurals use a `|one` suffix on the key. Only the variants a language needs are
declared:

```ts
"{n} liên hệ": "{n} contacts",
"{n} liên hệ|one": "{n} contact",
```

## Interface language

- Detected from `navigator.languages` on first visit, then persisted in
  `localStorage` under `nep-mail-locale`.
- Switchable from the globe selector in the top bar and from **Settings →
  Ngôn ngữ**.
- `<html lang>` is updated live, and dates/numbers use `Intl` with the locale
  tag (`vi-VN`, `pt-BR`, `zh-CN`, …).
- API requests send `Accept-Language`, so validation errors and delivery
  readiness reasons come back in the interface language.

## Email language

Each campaign stores its own `locale` (database column `campaigns.locale`).
It controls the message chrome (`Sent by … with Nếp Mail`, `Unsubscribe`) and
the public opt-out page linked from the email — the link carries `&l=<code>`,
so a recipient who never opens the app still sees their language. The body is
authored by you and is never machine-translated.

Starter templates exist in Vietnamese and English; other interface languages
fall back to the English starter set. Your own campaigns are unaffected.

## Adding a language

1. Add the code to `LOCALES` in `src/core/i18n.ts` with its native name and
   BCP 47 tag.
2. Copy `src/core/locales/en.ts` to `src/core/locales/<code>.ts`, rename the
   export, and translate the values. Keep keys byte-identical, keep every
   `{placeholder}`, and add `|one` variants where the language needs them.
3. Import the pack in `src/core/i18n.ts` and add it to `PACKS`.
4. Run `pnpm test` — `tests/i18n.test.ts` fails on missing keys, empty values
   or dropped placeholders.
5. Add the language to the table above.

Prefer natural product wording over literal translation. Product names
(`Nếp Mail`, `Nếp HR`, `Nếp Business`) stay untranslated.

## What is deliberately not translated

- Campaign content written by the operator.
- Audit log actions (`campaign.queued`, `key.revoked`, …): stable identifiers
  for machine consumption.
- Sample data (names, addresses) used in previews.
